1. Softverski zahtevi – Dijagram slučajeva korišćenja

Aplikacija KoncertApp pruža četiri glavna slučaja korišćenja grupisana u dva Feature-a koji su implementirani na frontendu i backendu. Identifikovani su sledeći akteri:

  • Posetilac – anoniman korisnik koji pristupa javnom delu aplikacije.
  • Kupac – korisnik koji je izvršio rezervaciju i poseduje email + token.

1.1 Opisi slučajeva korišćenja

ID Naziv Akteri Opis i tok Preduslovi / Alternativni tok
UC1 Pregled informacija o koncertu Posetilac Korisnik otvara početnu stranicu aplikacije. Sistem prikazuje naziv, datum, lokaciju i grad, dostupne zone sa kapacitetom i cenom po karti, rok early bird i opcionalne dodatne informacije. Nema preduslova. Nema alternativnog toka.
UC2 Rezervacija karata Posetilac 1. Korisnik odabira zonu i broj karata.
2. Unosi lične podatke (ime, prezime, kompanija*, adresa, email).
3. Opciono unosi promo kod.
4. Sistem validira kapacitet zone i promo kod (ako postoji).
5. Sistem obračunava ukupnu cenu (early bird → 5. karta po zoni → promo).
6. Sistem kreira rezervaciju, generiše jedinstveni token i promo kod za ovu rezervaciju.
7. Korisnik dobija potvrdu sa tokenom i promo kodom. 		Pre: Slobodna mesta u zoni.

Alt 1: Nema slobodnih mesta → greška 400.
Alt 2: Nevalidan/iskorišćen promo kod → greška 400.
UC3 Pregled i izmena rezervacije Kupac 1. Kupac unosi email i token na stranici „Moja rezervacija".
2. Sistem prikazuje detalje rezervacije.
3. Kupac može dodati ili ukloniti karte (uz ograničenje dostupnim mestima).
4. Sistem ponovo obračunava cenu sa istim pravilima popusta.
5. Sistem ažurira rezervaciju i prikazuje novu ukupnu cenu. 		Pre: Rezervacija u statusu Active.

Alt 1: Nevalidan email/token → 401.
Alt 2: Nema slobodnih mesta pri dodavanju → 400.
UC4 Otkazivanje rezervacije Kupac 1. Kupac unosi email i token i potvrđuje otkazivanje.
2. Sistem postavlja status rezervacije na Cancelled.
3. Token postaje trajno neaktivan (više se ne može koristiti za pristup).
4. Promo kod koji je ova rezervacija generisala (ako nije iskorišćen) dobija status Cancelled.
5. Ako je promo kod ove rezervacije već bio iskorišćen od strane druge rezervacije, on ostaje Used, ali se efekt (−5%) ne poništava na drugoj rezervaciji. 		Pre: Rezervacija u statusu Active, validan email + token.

Alt 1: Rezervacija već otkazana → 400.

PopustUslovIznosRedosled primene

Promo kod Validan promo kod koji korisnik unese −5% na ukupan zbir svih karata 3. (primenjuje se na ukupan zbir posle oba prethodna popusta)

2. Logički model podataka – PMOV

Logički model sadrži četiri entiteta koji opisuju domenu rezervacije karata za koncert. Model je normalizovan do 3NF. Podaci kupca su denormalizovani i smešteni direktno u entitetu Rezervacija jer jedan kupac može imati više rezervacija pod različitim imenima (porodica, prijatelji), pa se ne izdvaja kao zasebni entitet.

2.1 Opis entiteta

EntitetOpisKljučni atributi
Concert Podaci o koncertu (jedan u sistemu). Sadrži rok early bird koji se koristi pri obračunu cene. Id (PK), EarlyBirdDeadline
Zone Zona u okviru koncertnog prostora (VIP, Parter, Balkon itd.). Svaka zona ima sopstveni kapacitet i cenu po karti. Slobodna mesta se ne čuvaju kao atribut – računaju se dinamički kao Capacity - SUM(TicketCount) aktivnih rezervacija (zaštita od race conditiona). Id (PK), ConcertId (FK)
Reservation Rezervacija u okviru jedne zone. Sadrži sve podatke o kupcu, broj karata, obračunatu ukupnu cenu, token za autentifikaciju i zastavicu da li je primenjen early bird. Jedna rezervacija generiše tačno jedan promo kod i može koristiti tačno jedan promo kod drugog kupca. Id (PK), ZoneId (FK), Token (UK), UsedPromoCodeId (FK?)
PromoCode Promo kod koji se generiše za svaku rezervaciju i može biti prosleđen prijatelju. Prati ko je vlasnik koda i koja rezervacija ga je iskoristila. Kod postaje nevalidan kada vlasnik otkaže rezervaciju. Id (PK), Code (UK), OwnerReservationId (FK, UK), UsedByReservationId (FK?)

    autonumber

    Kupac->>FE: Popuni formu (zona, br. karata, podaci, promo?)
    FE->>CTR: POST /api/reservation (CreateReservationDto)
    CTR->>SVC: CreateAsync(dto)

    SVC->>DB: SELECT Zone (+Concert) WHERE Id = ZoneId
    DB-->>SVC: zona, EarlyBirdDeadline

    SVC->>DB: SUM(TicketCount) aktivnih rezervacija u zoni
    DB-->>SVC: zauzetaMesta

    alt Nema dovoljno slobodnih mesta
        SVC-->>CTR: throw InvalidOperationException
        CTR-->>FE: 400 Bad Request
        FE-->>Kupac: Prikaz greške
    end

    opt Korisnik je uneo promo kod
        SVC->>DB: SELECT PromoCode WHERE Code = dto.PromoCode AND Status = Active
        DB-->>SVC: promoKod
        alt Promo kod ne postoji ili nije Active
            SVC-->>CTR: throw InvalidOperationException
            CTR-->>FE: 400 Bad Request
            FE-->>Kupac: Prikaz greške
        end
    end

    SVC->>PRC: CalculateTotal(price, count, isEarlyBird, hasPromo)
    Note over PRC: 1) Early bird: unitPrice = base × 0.90
2) Svaka 5. karta × 0.50 od unitPrice
3) Promo: total × 0.95
    PRC-->>SVC: ukupnaCena

    SVC->>DB: BEGIN TRANSACTION
    SVC->>DB: INSERT Reservation (Token = Guid, TotalPrice, IsEarlyBird, ...)
    DB-->>SVC: reservationId
    SVC->>DB: INSERT PromoCode (Code, OwnerReservationId = reservationId, Status = Active)
    DB-->>SVC: promoCodeId

    opt Iskorišćen tuđi promo kod
        SVC->>DB: UPDATE PromoCode → Status = Used, UsedByReservationId = reservationId
        SVC->>DB: UPDATE Reservation → UsedPromoCodeId
    end

    SVC->>DB: COMMIT
    DB-->>SVC: OK

    SVC-->>CTR: ReservationResponseDto (Token, TotalPrice, GeneratedPromoCode, ...)
    CTR-->>FE: 201 Created
    FE-->>Kupac: Potvrda: token + promo kod
